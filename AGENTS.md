# Sharp

Sharp is standalone. Do not import app or resume2. Existing personal master files are outside its scope.

Core modules may import contracts and other core modules, never adapters or vendor SDKs. The entry point composes adapters. Keep explicit function dependencies and small modules.

Define contracts and functionality tests before changing behavior. Do not weaken assertions to make implementation pass. Document intentional requirement changes separately.

The user-approved defaults bold names, target roles, section/employer headings and education rows; body/bullet text stays regular. Typography, colors and list geometry live in settings styles, never renderer constants. No personal facts in public fixtures. Never infer user confidence, strengthen contribution levels, or remove claim qualifiers. Career edits are proposals until approved by a matching revision.

Use MCP/CLI customization operations to change user settings. Custom functions belong in the local settings file, not core source. New capabilities require explicit contract/adapter changes; do not promise unrestricted behavior.
